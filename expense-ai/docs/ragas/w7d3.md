## Expected Mechanism of Each Upgrade

### Hybrid retrieval (`use_hybrid=True`)
Dense retrieval can miss documents that contain exact product codes or rare terminology not
captured by the embedding space.  Sparse BM25-style FTS (`websearch_to_tsquery` + `ts_rank_cd`)
finds those documents, and RRF fusion (rank-based, no score normalisation) re-ranks the merged
list without introducing a scale mismatch between the two signals.  Expected effect: higher
**context_recall** because relevant chunks that dense misses can be surfaced by FTS.

### MMR diversification (`use_mmr=True`)
Without diversity control, the top-k dense results are often near-duplicate passages from the
same section of a document, wasting the context window.  Greedy MMR (λ=0.7) picks candidates
that are relevant to the query *and* dissimilar from already-selected passages.  Expected effect:
higher **context_precision** (fewer redundant passages means each slot adds new information);
marginal improvement in **faithfulness** because the model has less conflicting text to handle.

### BGE reranker (`use_rerank=True`)
Cross-encoder reranking (`BAAI/bge-reranker-base`) scores each (query, passage) pair jointly,
capturing fine-grained relevance that bi-encoder cosine similarity misses.  The 6-result top-k
window is small, so even modest precision improvements have a large relative effect.  Expected
effect: higher **faithfulness** (the most directly relevant passage is now ranked first, giving
the LLM a cleaner grounding signal) and higher **answer_relevancy**.

### Metadata filter isolation (`use_filter=True`)
Without the filter, a multi-tenant query could theoretically pull context from another tenant's
documents.  `chunk_metadata @> %s::jsonb` pushes the tenant predicate into the ANN scan,
eliminating cross-tenant contamination.  Expected effect: no RAGAS score degradation (single-
tenant golden set), but critical for production security.
